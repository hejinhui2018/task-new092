# 骑马钉画册拼版台（Saddle-Stitched Imposition Desk）

一个完全运行在浏览器内的印前拼版与装订决策工具：制作人员在送印前即可看清**每张印张正反面的页码位置、制版朝向、装订边、裁切线与出血区**，逐页翻阅折叠成书后的真实页序；装订主管还能在配页前登记**各折手正反面的合格到货数量、色批与检验状态**，实时掌握现存印张**能装成多少本、短板在哪、补印哪几块版最省开机次数**。

使用 React + TypeScript + Vite 实现，核心算法（拼版、成套分配、补印排序、历史迁移）为纯函数并配有单元测试，无后端、无外部服务，数据只保存在浏览器本地。

## 运行方式

```bash
# 1. 安装依赖（Node 18+）
npm install

# 2. 启动开发服务器（默认 http://localhost:5173）
npm run dev

# 3. 运行测试（一次性）
npm test
#    或监听模式
npm run test:watch

# 4. 生产构建（先 tsc 类型检查，再打包到 dist/）
npm run build

# 5. 本地预览生产构建
npm run preview
```

## 功能说明

### 拼版预览（原有）

- **首屏内置 16 页产品手册**：标准 4 帖骑马钉书，最外帖配对为正面 `16 | 1`、背面 `2 | 15`，向内依次收敛。
- **左侧页面栏（阅读顺序）**：拖动排序、增删页面，编辑印刷页码、出血量、来稿倒置标记。
- **自动补白**：页数不是 4 的倍数时在封底（最后一页）之前插入空白页。
- **印张视图**：正反面分开绘制，标注阅读序号、制版旋转角（0°/180°）、印刷页码、装订边、裁切线与出血区。
- **长边 / 短边翻面切换**：长边四版正向、槽位左右并排；短边两个上槽制版旋转 180°、槽位上下叠放。
- **逐张折叠预演**：弹窗模拟成书翻阅（方向键 / 空格 / 进度条，Esc 关闭）。
- **版面检查**：缺页、重复页、倒置、出血不足、补白提示。

### 折手库存与补印决策（新增）

首屏在内置 16 页手册的基础上自带**两色批（A/B）、一处短缺**的示例库存：第 3 帖 A 批 500 张中有 30 张运输破损、正面报废，仅 470 张合格；B 批每帖各 120 张。交付目标预置 600 本。

- **库存矩阵**：按折手（= 拼版的每一张纸）分组登记各印刷批次的
  - 正面 / 背面合格数量；
  - 色批（可自由改名，如 A、B、专色…）；
  - 每面检验状态：**合格 / 待复检 / 报废**（点击状态钮循环切换）。
  - 硬规则：**同一折手的正反面必须来自同一批次且两面均合格**，单条记录的成套能力取 `min(正面, 背面)`；任一面待复检/报废则该批印张暂不装订，矩阵就地给出原因（如「正面已报废」「正反面合格数不一致…仅 N 张可同批配套」）。

- **成套批次（确定性分配，不是各折手最小值）**：系统按完整折手集合把现存印张组成书册——
  1. 先**单色批各自配套**（A 批只与 A 批、B 批只与 B 批）；
  2. 单色配套后仍有散张，再按**现存色批全混用**兜底（不同帖允许来自不同批，同帖正反面仍须同批）。

  实时给出：**现存可装订本数、已锁定/水填数量、断供折手、短板折手、各帖未配套余量与浪费总张数**。示例中 A 批单色 470 本、B 批单色 120 本，合计 590 本，其余三帖各余 30 张。每批水填方案可一键**锁定**（锁定批次优先保留、占用印张不得再分配），也可解锁。

- **补印决策**：输入交付目标后，系统为每种色批通道生成补印候选，并按
  **开机版组数 → 补印印张数 → 剩余浪费**三级确定性排序，逐帖解释「第 N 帖交 X 批补印 M 张、正反面同批一次上机，补齐第 a–b 本」。
  - 示例目标 600 本：最优方案只需 **1 组版、补印 10 张**（第 3 帖 A 批 +10，B 批 120 本照旧）；B 批单色方案需 4 组版 40 张，排在最后。
  - 补印一张 = 该帖正反面两块版同批一次上机；方案采用后换发正式到货批次入库并重算成套。
  - **无解时明确指出约束**：目标低于已锁定数、无折手、目标非正数等均给出原因。

- **首屏联动**：每张印张卡片右上角的库存徽标显示该帖合格/锁定/可配数量（断供红色），点击平滑滚动并高亮矩阵中的对应折手；数量或状态改变后，矩阵、成套批次、顶栏可装订数与补印清单即时重算。

- **撤销 / 重做与刷新恢复**：所有结构性变更（编辑页面/库存、锁定、采用补印方案等）进入历史栈，支持按钮与 `Ctrl/⌘+Z`、`Ctrl/⌘+Shift+Z`（或 `Ctrl+Y`）；交付目标输入与折叠预演位置为瞬态、不入栈。整个历史信封持久化在 `localStorage`（键 `saddle-stitch-desk:v2`），刷新后仍可继续撤销/重做；旧版 `v1` 数据自动迁移（页面与翻面设置保留，库存初始化为空）。

## 成套与补印规则速查

设一本书需要折手集合 `{0,…,S-1}`：

- 单条到货记录能力 `cap = 正面背面均合格 ? min(frontQty, backQty) : 0`。
- 水填规则链：`单色批 A → 单色批 B → … → 全色批混用`；每轮在规则允许的批次内、按确定顺序（id 升序）为每帖选一批，取整条链的最小余量成套，因此**批次不兼容时不会跨批错误凑套**。
- 含全混用兜底时，现存最大可装订数 = 各折手总合格能力的最小值（但分配明细仍按单色优先、混用兜底给出，而非简单取最小值）。
- 补印候选：
  - 单色批 X：其他色批现存单色书册照旧产出，X 批每帖自由余量（能力减去锁定占用）补到 ≥ `目标 − 锁定 − 其他批单色数`；
  - 全混用：每帖总合格能力补到 ≥ 目标，缺口帖交该帖现存能力最强的色批上机；
  - 每个候选都经完整规则链仿真验证「采用后确实达标」，再按 版组数/印张数/浪费 排序；补印行完全相同的候选合并，等价时单色批优先。

## 目录结构

```
src/
  types.ts                 领域模型（页面/翻面/槽位 + 库存批次/成套/补印）
  state.ts                 v2 历史信封、commit/undo/redo、localStorage 持久化与 v1 迁移
  App.tsx                  布局、状态编排与撤销重做快捷键
  lib/
    imposition.ts          补白 + 骑马钉页码配对 + 翻面旋转
    fold.ts                折叠后阅读顺序
    diagnostics.ts         缺页/重页/倒置/出血/补白检查
    inventory.ts           库存规整、成套分配、总览、补印候选排序、锁定/采用/迁移规整
    sample.ts              内置 16 页手册 + 两色批短缺库存示例
    uid.ts                 唯一 id
    *.test.ts              核心算法单元测试（Vitest）
  components/
    StockMatrix.tsx        折手库存矩阵（数量/色批/检验状态）
    KitsPanel.tsx          可装订数、短板、余量、锁定/水填批次
    ReprintPanel.tsx       交付目标、补印候选排序与逐案解释
    InventoryDesk.tsx      库存工作台容器
    PageList / SheetCard / SlotView / PreviewModal / IssuesPanel / LeafArt
```

## 测试覆盖

`npm test` 运行 6 个测试文件、共 73 个用例，覆盖：

- 拼版：补白位置、16 页标准配对、长边/短边翻面的槽位/旋转/装订边差异；
- 折叠阅读顺序与版面诊断（缺页、重复、倒置、出血、补白）；
- **库存规整**：确定性排序、越界孤儿丢弃、正反面取小、待检/报废归零、陈旧锁定截断；
- **成套分配**：单色批最小值、先单色后混用兜底、跨批不兼容不凑套、待检/报废不参与、确定性、锁定保留与失效锁批自动放弃、短板/断供/余量/浪费总览；
- **补印决策**：示例 590→600 的最优 1 组版 10 张、A/B/混用候选版组数与印张数、排序与去重、书册区间解释、目标低于锁定数等无解约束；
- **锁定/解锁、采用补印发正式批次、页面增减后的库存迁移规整**；
- **历史栈**：commit/undo/redo、100 条截断；**持久化与迁移**：v1→v2、v2 信封（含 past/future）刷新恢复、损坏回退示例；
- App 首屏 SSR 冒烟渲染（含库存矩阵、590 本、补印指标、撤销重做联动）。
